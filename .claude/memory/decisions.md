## ADR-1 (2026-07-19): "Независимость" бывает двух разных типов

**Контекст:** ai-hyp-gate тест на идее "Keiper-Li через Stieltjes-константы" показал,
что claim "независимая линия evidence" смешивал два разных понятия.

**Решение:** различать явно —
1. Независимость **механизма/явления** (разные техники объясняют одно наблюдение —
   так устроена настоящая "стена" A-07/A-09/A-12).
2. Независимость **способа вычисления** одного и того же строго определённого числа
   (Connon-рекуррентность vs zero-free формула для одного и того же λ_n — это
   arithmetic cross-check, НЕ новая линия evidence).

**Почему:** только тип 1 увеличивает научную confidence в конвергенции; тип 2 даёт
только валидацию инфраструктуры (полезно, но другого порядка ценности). Смешение
этих типов — источник overclaim'а, ровно тот паттерн, который проект ловит у Grant.

**Применение:** при формулировке любого будущего "независимого подтверждения" —
явно указывать, какой это тип.

## ADR-2 (2026-07-19): 143MB CSV в истории связанного репо — не переписывать shared history

**Контекст:** skeptic-engine-manuscript's `main` содержит коммит с 143MB CSV,
блокирующий push. Ветка с переносимым H-12 кейсом унаследовала эту историю.

**Решение:** НЕ делать git filter-repo/BFG (переписывание истории всего репо,
force-push, риск для других feature-веток). Вместо этого: cherry-pick нужного
коммита на свежую ветку от чистого `origin/main`.

**Почему:** тот же контент (2 файла, 128 строк) достигается без риска для
`feature/estimand-gap-closure`, `feature/golden-set-clean` и других веток,
разделяющих проблемного предка. Cost/benefit явно в пользу cherry-pick, когда
переносимый diff мал и изолирован.

**Применение:** тот же паттерн — если снова понадобится перенести малый, изолированный
diff из ветки с "испорченной" историей, cherry-pick на чистую ветку почти всегда
дешевле и безопаснее полного rewrite.

## ADR-3 (2026-07-19): Численные атомы на большем масштабе — считать дороже, чем оценка идея-генератора

**Контекст:** за один день 3 из 4 попыток Track R (B-01/Connes, B-06/Speiser,
close-pair/B-03 revival) оказались дороже, чем "TEST_NOW/дёшево" из
boyko-goal-expansion-100 и combinatorial-creativity.

**Решение:** при оценке новой численной идеи по шкале "дёшево/1 сессия" — явно
проверять, требует ли она (а) 2D-поиск нулей вместо 1D-скана вдоль прямой,
(б) разрешение осцилляции на масштабе x≫100, (в) различение близко расположенных
объектов. Если да — по умолчанию НЕ доверять "дёшево" оценке генератора идей без
собственной прикидки стоимости.

**Почему:** три конкретных провала за один день — не совпадение, а структурный
паттерн: идея-генераторы (boyko-goal-expansion-100, combinatorial-creativity)
не моделируют численную стоимость дискретизации/precision scaling.

**Применение:** для следующего Track R атома — прогнать быструю прикидку стоимости
(1-2 пробных вызова) ДО написания полного FL claim.md, не после.
