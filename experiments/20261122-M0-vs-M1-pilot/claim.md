# Pilot M0 vs M1 — предрегистрация (написана ДО запуска, 2026-11-22)

**L0:** Predictive/Descriptive. Измеряем, сколько из 6 задач решает каждый метод. Причинных выводов о «почему» не делаем.
**Статус:** hypothesis-generating pilot. Не подтверждает превосходство метода.

## Вопрос
Даёт ли протокол «граф обязательств» (M1) больше независимо принятых Lean-доказательств, чем одиночный агент (M0), при равных условиях?

## Методы
- **M0:** один агент, получает файл с задачей и доказывает его напрямую. Может запускать компилятор.
- **M1:** тот же агент (модель, лимиты, компилятор), но обязан по протоколу: 1) выписать план доказательства как список промежуточных лемм с зависимостями; 2) доказать каждую лемму отдельным файлом с `sorry` для остальных; 3) собрать итоговый файл.

## Равные условия
- Модель: sonnet, свежий контекст, без доступа к другим вариантам.
- Лимит: не более 10 запусков `lean` на задачу.
- Среда: только ядро Lean v4.33.1, без Mathlib.
- Задачи: 6 файлов `tasks/T1..T6.lean` (определения собственные, формулировки заморожены).

## Независимая проверка
`grade.sh`: формулировка не изменена, компиляция без ошибок, нет sorry/axiom/native_decide и т. п., `#print axioms` только `propext`, `Classical.choice`, `Quot.sound`.
Контроли проверяющего (пройдены до запуска): известное решение T5 = PASS; заглушка = FAIL; неверное доказательство = FAIL; изменённая формулировка = FAIL.

## Регистрируемые метрики
Основная: число задач PASS на метод (из 6). Вторичные: число запусков `lean` и токены (по отчёту агента, не проверяются независимо).

## Design detectability (EstimandOps)
`n=6 задач на метод, 1 прогон каждая; baseline_or_sigma=неизвестен (нет базовой доли успеха M0); alpha=0.05; power=0.8; MDE=undetectable; MCID=разница ≥2 задач`.
Следствие: статистически значимого различия этот пилот обнаружить не может. Любой результат трактуется только как оценка осуществимости.

## Критерии (фиксированы заранее)
- **Promising:** M1 решает ≥ на 2 задачи больше M0.
- **No signal:** разность ≤1 по модулю. Фраза в отчёте: «не обнаружено при MDE=undetectable, n=6».
- **Worse:** M0 решает ≥ на 2 больше. Тогда M1-протокол не рекомендуется без пересмотра.
- Результат в любом случае не называется «подтверждением» или «опровержением» метода.

## Что результат НЕ означает
1. Не доказывает превосходство M1 в открытой математике (задачи элементарные и решённые).
2. Не исключает утечку: похожие доказательства могли быть в обучении модели; задачи с собственными определениями снижают, но не устраняют риск.
3. Не оценивает Skeptic Engine / FL (это не M1) и не переносится на RH.
4. n=1 прогон на задачу: случайность модели не усреднена.

## Известные слабости дизайна
- Оба метода используют компилятор, поэтому различается только организация доказательства.
- Расходы токенов самоотчётные.
- Изоляция агентов обеспечена инструкцией, не файловой системой.
